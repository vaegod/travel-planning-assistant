# 智能规划使用说明

智能规划基于 Spring AI 和模型工具调用，结合景点、路线、预算与行程规则生成可预览的旅行计划。

## 使用流程

1. 登录后，从首页进入“试试智能规划”。
2. 输入目的地、1～7 天的出行天数、单人预算和偏好，选择步行、公交或自驾。
3. 等待规划、工具查询和行程校验，检查草稿及提示后确认保存。
4. 在已保存行程中选择“调整这份行程”，指定日期和时段，填写修改要求并预览变化。
5. 确认后保存为新版本，也可以围绕行程继续咨询。

局部调整保留未选活动，重新计算受影响的相邻路段、门票合计和已知交通费用。保存时检查行程版本，避免覆盖其他修改。

## 景点、路线与预算

配置高德 Web 服务 Key 后，系统使用真实地点查询及步行、公交、自驾路线接口核验所选景点与路段。公交方案按查询时的信息返回，不保证未来班次；自驾通行费不包含全部油费和停车费。

可以在规划页面提供景点最短游览时间或门票预留参考。系统只对实际安排到的对应景点执行这些约束；参考值由用户或调用方提供，不视为高德实时票价。未提供参考值时，费用与游览时间为估算。

预算按单人目的地内支出计算，包括住宿、餐饮、门票、当地交通和其他费用，不包括往返目的地的大交通。项目默认预留住宿 200 元／晚、餐饮 80 元／天和其他费用 20 元／天，作为预算假设；预算不足以覆盖必要预留时会说明原因。

未配置高德 Key 时，仍可生成和校验参考行程，但地点及路线会标记为未核实。地图服务异常会作为服务错误处理；无法规划的请求会展示原因，不生成可保存的行程。

## 配置

Docker Compose 用户在 `deploy/compose.env` 中配置，开发环境用户在 `travel-java-server/.env` 中配置：

| 变量 | 用途 | 默认值 |
| --- | --- | --- |
| `LLM_API_KEY` | 模型服务密钥 | 必填 |
| `LLM_BASE_URL` | 兼容 OpenAI 接口的服务地址 | 配置示例中的地址 |
| `LLM_MODEL` | 模型名称 | 配置示例中的模型 |
| `AMAP_API_KEY` | 高德 Web 服务 Key | 空 |
| `AGENT_TIMEOUT_MS` | 单个规划任务的总时限 | 240000 毫秒 |
| `AGENT_MAX_ROUNDS` | 模型请求轮数上限 | 8 |
| `AGENT_MAX_TOOL_CALLS` | 工具调用次数上限 | 16 |

高德 Key 只由后端使用。模型或地图连接出现可恢复故障时，系统会在任务限制内尝试恢复；取消、服务错误和不可行结果分别处理。

## 实现与验证

Vue 页面负责收集需求、展示进度与差异预览；Spring Boot 使用 Spring AI 的 ChatClient 和工具调用能力，将地点、路线、预算与行程检查接入规划过程。后端校验通过的草稿由用户确认后保存，MySQL 记录行程版本和会话。

独立评测覆盖新建、局部调整和不可行请求，使用固定参考数据与模拟路线。[评测方法和结果](../eval/agent-v1/README.md)介绍数据来源、评分规则及适用范围。
