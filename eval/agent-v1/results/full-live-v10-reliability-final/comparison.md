# Agent优化后的同集回归对比

基线：full-live-v9-convergence；复测：full-live-v10-reliability-final。数据、独立评分器、共享任务协议、模型参数及节流配置一致，80个配对结果逐一核验。

相对v9，本轮将同一共享参考表的ticketBudget增加为带来源的API门票下限，由Java执行；这是额外的结构化事实绑定，不能作为纯模型能力提升。

传输策略变化：每次Agent模型请求最多75秒、每任务最多一次新连接恢复，仍受原8轮和总时限限制；转发器对两组关闭空闲连接自动断开。首次通过指未使用传输恢复且任务规则通过，正常规划/修正轮次仍允许；恢复请求耗时与之前失败等待分别记录，所有物理尝试均计入成本，无整条任务补跑。

这40条已经用于缺陷定位，本次为同集回归复测。原holdout分组名称保留便于对照，不能再次视作未见数据的泛化验证。单次随机模型输出与不同采集时段都会影响结果；不声称统计显著性或线上效果。路线为离线合成，未测试真实高德服务准确率。

预算、门票、游览时长等剩余规则失败仍保留在逐条报告中；本轮不修改评分器、不按失败重跑。模型工具调用与后端自动地图核验分别计数，节流等待计入端到端耗时。

地图连接重连记录：基线38次，本次0次。它属于同一任务内、最多一次的只读GET重连，不是模型请求或整条用例重跑；地图HTTP数仅统计回放端实际收到的请求。
