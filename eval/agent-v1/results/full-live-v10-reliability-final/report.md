# 旅游规划 Agent 适配评测报告

运行：full-live-v10-reliability-final；阶段：full；模式：live；模型：Qwen/Qwen3.5-35B-A3B。

## 评测口径

本轮对照基线为full-live-v9-convergence，使用同一40条用例作缺陷修复后的回归复测。原holdout分组已经用于定位缺陷，此处保留名称便于对照，不能视为未见数据的泛化验证。修复前后比较见同目录comparison.md。

- 基于ChinaTravel改编的单人目的地内任务，非ChinaTravel官方成绩；原题ID和改动保存在数据集。
- 两组使用相同模型、temperature、思考配置、输出上限和固定参考事实；Agent运行本次归档代码的生产提示词、工具及后端规范化，一次生成组无工具、无修复。比较的是应用流程，不是两个不同模型。
- Agent沿用项目既有住宿/餐饮/其他费用预留基准，明显低于必要预留的预算由Java直接拒绝，模型调用记0；审核必须验证请求天数、预算、各项预留和拒绝证据，不能用通用报错冒充零调用成功。两组任务共享说明中的费用基准保持一致。
- 本轮把两组原已共享参考表的景点游览下限，映射为Agent API的结构化visitRequirements，由服务端保存并执行。该输入适配属于本次改造；审核核对调用方传值及服务端回显，来源仅为共享公开参考字段，不读取expect标签或评分结果。高德接口不被描述为提供这些游览下限。
- 相对v9，本轮增加同一共享参考表ticketBudget到Agent API门票预留约束的结构化绑定，服务端按来源校验；不是实时高德售价，也不读取隐藏评分标签。
- 模型每次物理请求最多75秒，每个任务最多一次显式传输恢复，使用新连接，仍受8轮和任务总时限限制。仅在未取得可用响应时恢复，不重放已完成工具。首次通过指任务未使用传输恢复且独立规则通过，包含正常规划及草稿修正轮次；含恢复通过为最终结果。额外耗时是恢复请求实际耗时，恢复前失败等待另列，全部计入端到端。转发器对两组均关闭空闲连接自动断开；与v9存在明确的传输策略变化。
- 地点来自固定的ChinaTravel景点子集；路段距离/时间/费用由明确的离线公式模拟，不评估实时高德可用性、真实票价、营业时间或日期安排。
- 每条每组一次正式尝试，不因评分失败重试；单次调用的失败及用量缺失均保留。同时运行的任务对上限为1。
- 全局节流：新请求间隔至少5000ms；滚动60秒预留Token预算40000，请求返回后按实际usage回补。429后后续请求等待65秒；失败的当次请求不重试。队列等待计入端到端耗时。
- 主指标为应完成任务的独立规则全部通过率；不可行预算和无公交方案另统计正确拒绝，通用报错不算正确拒绝。评分独立于应用AgentRules。
- 这是小样本单次运行，无统计显著性或真实用户收益结论。Token仅列供应商返回的已知用量，未绑定价目表，不估算金额。

- 正确拒绝只检查拒绝决定及原因类别，不认证解释中每个数字；末轮关键词命中仅供诊断，不等同于模型正确拒绝。Token统计仅对应本报告中的唯一尝试，不代表全部预检或账户账单。
