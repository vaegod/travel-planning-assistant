# 旅游规划 Agent 适配评测报告

运行：full-live-v5-routes；阶段：full；模式：live；模型：Qwen/Qwen3.5-35B-A3B。

## 评测口径

本轮对照基线为full-live-v3，使用同一40条用例作缺陷修复后的回归复测。原holdout分组已经用于定位缺陷，此处保留名称便于对照，不能视为未见数据的泛化验证。修复前后比较见同目录comparison.md。

- 基于ChinaTravel改编的单人目的地内任务，非ChinaTravel官方成绩；原题ID和改动保存在数据集。
- 两组使用相同模型、temperature、思考配置、输出上限和固定参考事实；Agent保留现有生产提示词、工具及后端规范化，一次生成组无工具、无修复。比较的是应用流程，不是两个不同模型。
- 地点来自固定的ChinaTravel景点子集；路段距离/时间/费用由明确的离线公式模拟，不评估实时高德可用性、真实票价、营业时间或日期安排。
- 每条每组一次正式尝试，不因评分失败重试；单次调用的失败及用量缺失均保留。同时运行的任务对上限为1。
- 全局节流：新请求间隔至少5000ms；滚动60秒预留Token预算40000，请求返回后按实际usage回补。429后后续请求等待65秒；失败的当次请求不重试。队列等待计入端到端耗时。
- 主指标为应完成任务的独立规则全部通过率；不可行预算和无公交方案另统计正确拒绝，通用报错不算正确拒绝。评分独立于应用AgentRules。
- 这是小样本单次运行，无统计显著性或真实用户收益结论。Token仅列供应商返回的已知用量，未绑定价目表，不估算金额。

- 正确拒绝只检查拒绝决定及原因类别，不认证解释中每个数字；末轮关键词命中仅供诊断，不等同于模型正确拒绝。Token统计仅对应本报告中的唯一尝试，不代表全部预检或账户账单。

- 一次生成：35/38个正例返回行程JSON，其中15个全部规则通过；负例正确拒绝2/2。
- 工具调用 Agent：23/38个正例返回行程JSON，其中23个全部规则通过；负例正确拒绝2/2。
- 主分数之外，应同时检查未交付草稿、参考事实漏检与调用开销。当前样本不支持把增加工具轮数本身当作效果提升。
