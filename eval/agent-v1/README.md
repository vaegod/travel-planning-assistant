# 旅游规划评测

使用独立 Node.js 评分程序评估旅游规划助手的行程质量。评测覆盖新建行程、局部调整和不可行请求，并记录模型调用次数、端到端耗时与失败结果。

## 数据和场景

- **40 条固定回归场景：**30 条根据 ChinaTravel 需求适配，另有 8 条局部调整和 2 条不可行场景。
- **20 条新增场景：**14 条根据未用于项目调试的 ChinaTravel 需求适配，另有 4 条局部调整和 2 条不可行场景。场景首次执行前已固定；执行后可用于回归。
- 任务范围统一为单人、目的地内出行；不评估往返目的地交通、真实预订或未映射的原始要求。

景点名称、位置、参考门票与游览时长取自固定版本的 ChinaTravel 配套数据；住宿、餐饮等费用采用项目假设。路段距离、时间及费用由固定公式模拟，不调用实时高德路线。数据来源、许可证和改编细节见 [归属与适配说明](ATTRIBUTION.md)。

## 评分方式

评分器读取行程和固定参考表，独立检查：

1. **预算：**检查费用合计、预算上限、景点门票预留与约定的费用下限。
2. **地点与路线：**核对景点及出行方式，检查相邻景点路线可用性和交通耗时；输出路线信息时核对其一致性。
3. **时间：**检查游览时长下限，并将游览与参考交通耗时计入每日总时长。
4. **局部调整：**核对指定修改范围，保留未选活动内容，并检查受影响路段。
5. **不可行请求：**分别统计明确拒绝；一般服务错误不计为正确拒绝。

可行任务只有在全部适用规则通过时才计为成功。评分程序不调用后端生产校验器，也不使用模型打分。不可行请求的评分检查拒绝决定与原因类别，不验证解释中的每个数字。

## 对照结果

两组使用同一模型、参数和共享参考事实。一次生成组不使用工具或二次修正；智能体组运行应用的工具调用、服务端校验及有限修正流程。每条任务每组保留一次正式尝试，失败和超时计入结果。

| 场景 | 指标 | 一次生成 | 智能体 |
| --- | --- | ---: | ---: |
| 40 条回归 | 可行行程满足全部规则 | 13/38 | 38/38 |
| 40 条回归 | 不可行请求正确拒绝 | 2/2 | 2/2 |
| 20 条新增场景首次评测 | 可行行程满足全部规则 | 3/18 | 18/18 |
| 20 条新增场景首次评测 | 不可行请求正确拒绝 | 1/2 | 2/2 |
| 20 条新增场景首次评测 | 平均模型请求数 | 1.00 | 2.10 |
| 20 条新增场景首次评测 | 端到端耗时 P50 | 25.140 秒 | 34.275 秒 |
| 20 条新增场景首次评测 | 端到端耗时 P95 | 39.162 秒 | 50.566 秒 |

耗时包含任务等待与评测节流；一次生成组有一次超时，已保留在分母中。两组调用资源不同，结果比较应用流程而非单独比较模型能力。回归集与新增场景不是逐条配对的前后对照。

样本来自同一组城市与固定景点来源，路线为离线模拟；该评测不代表真实地图服务质量、实时票价、营业时间或 ChinaTravel 官方成绩。已有 20 条新增场景在首次执行后已曝光，后续使用应作为回归数据。

```bash
node --test eval/agent-v1/*.test.mjs
```

```bash
node scripts/verify-agent-eval.mjs --input=eval/agent-v1/results/full-live-v10-reliability-final/results.json --archive=eval/agent-v1/baselines/full-live-v10-reliability-final
```
