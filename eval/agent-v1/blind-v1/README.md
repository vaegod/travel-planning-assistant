# 第一批20条盲测

应用基线为full-live-v10-reliability-final。原40条、原始结果、报告及80个测量源码保持不变；
本轮只新增独立盲测数据和执行/审核/报告脚本，不修改应用、提示词、工具、评分器、共享任务协议或模型配置。
v10 JAR与原80个源码文件逐字节核验。

## 预先固定的范围

20条分为14条新建、4条局部修改、2条明确不可行。覆盖三种出行方式、1～4天、
上午/下午/晚上/整天修改、固定费用差1元的低预算及没有公交方案。
需求来源为未在原40条采用的14个ChinaTravel Human UID；4条修改与2条负例由项目按预登记规则编写。

城市仍为原10城。地点从同一固定版本景点表中重新选取，排除原来源行、格式规范化后名称及坐标，
共80个新景点；按照预先定义的密集簇规则选择，路线公式、费用假设、参考字段与v10保持一致。
这验证的是相对项目调试历史未用过的输入/事实，不保证这些公开城市或景点未出现在模型预训练语料中。

原需求只保留目的地与天数，人数统一为单人，正例预算统一为目的地内1000元/天，往返城市交通与原未映射约束不保留。
交通、每日双景点、时间费用规则及部分类型要求为适配新增。原始约束程序只存档、不执行；
不是ChinaTravel官方任务或官方分数。

## 封存与首次执行

[plan.json](plan.json)先于构造固定采样、范围和解释规则，seed=20261025。
[seal.json](seal.json)记录数据、参考环境、构造脚本、原回归数据及v10应用的哈希。
[dataset.json](dataset.json)与[frozen-sandbox.json](frozen-sandbox.json)按新文件方式生成，拒绝覆盖。
18条正例只做既有独立评分器的静态可行性检查；未向Agent或模型运行这些用例作调试。

新执行脚本的模型、工具、调用/计分及Java启动代码与v10逐段核对；仅数据路径、封存与首次使用控制不同。
两组均使用同一组新事实。沿用v10的门票/游览参考绑定、有界恢复、调用上限与节流，
每条每组一次正式尝试；基础设施失败、修正及恢复成本都保留。

首次模型执行前原子创建exposure.json；此后拒绝第二次运行及fixture/pilot调试。
执行完即为已曝光数据，以后分析或改进时应将它标作回归材料，不能再次声称未见盲测。
已有40条仍保留原文件，v10完整结果继续作为回归基准；本轮没有重新执行原40条。

    node scripts/archive-agent-blind-eval.mjs --run=blind-live-v10-20

分别报告正例全部规则通过、明确拒绝、首次/含恢复通过、模型物理/捕获次数、工具调用、Token用量覆盖、
全部尝试的P50/P95、恢复请求与失败等待。与v10原40条只作分开描述，不计算逐条前后优化增益。
小样本一次运行及合成路线不代表真实高德准确率、统计显著性或线上收益。
